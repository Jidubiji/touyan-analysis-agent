# Fundamental Intelligence Agent V1.3.1 — 估值模块补丁说明

## 修改依据

谷歌估值讨论暴露出：当期GAAP净利润包含非经常性股权投资收益；简单TTM P/E可能显得异常便宜，TTM FCF又受到前置AI资本开支压低。对盈利持续、可合理预测每股盈利的公司，优先以**FY1正常化Forward P/E**作为估值起点，并以FY2、历史同口径分位、现金流/ROIC交叉验证更合理；但Forward P/E不能单独决定低估/高估。

## 修改文件与规则

- `AGENTS.md`：Module V新增V3（FY1/FY2正常化Forward P/E、EPS桥、数据时点及口径）/V4（3–5年同口径历史分位、85%显著提醒）/V5（FCF、CapEx、ROIC、稀释及权益价值交叉验证）；同步更新输入、Stage G、输出H、存储字段和质量闸门。
- `signal_rules.yaml`：版本 `1.3.1`，新增 `valuation_integrity` 下的主估值优先顺序、GAAP/Normalized对账、财年滚动、历史快照和85%提醒规则。
- `QA_TESTS.md`：原T01–T73原样保留；新增T74–T89共16项合成场景。**合计89项测试定义，不代表已执行。**
- `check_bundle.py`：仅做文件/规则/测试编号的静态检查，不验证财报数字或Agent真实性能。

## 防止误用

1. FY1/FY2是以研究时点和公司财年动态定义，不是永远的2027/2028年；2026年11月研究日历财年公司时，对应FY2027/FY2028。
2. 供应商Adjusted EPS不自动等于完整正常化EPS。非经常性投资收益、税项、股本变化应逐项核对；不能查证则标缺口。
3. 财报前beat/miss需要事前一致预期；当前Forward P/E使用估值日最近可得共识，严格分离。
4. 历史P/E必须有当时已发布的EPS预测；不足24个可比月度点或发生不可桥接的经营阶段硬断点，精确分位不可用。
5. ≥85%是历史高估值位置提醒，而不是自动卖出；历史分位低也不代表天然便宜。
6. 对亏损、接近零利润、周期顶点或商业模式重构公司的Forward P/E不可强制使用；改为适合的估值方法。
7. 所有EPS×倍数的股价仅作为敏感性；不等于完整目标价/安全边际。必须额外核对每股现金流、资本开支、投入回报及净稀释。
